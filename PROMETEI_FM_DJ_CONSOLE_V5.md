# PROMETEI FM — Управление музыкой в эфире (DJ Console v5)

## Что изменилось
- https://prometei-web-2.pages.dev/fm-studio: новый блок «Пульт прямого эфира» в космическом стиле.
- Защищённый каталог PC DJ с поиском по исполнителю/названию, загрузкой по 80 треков, текущим треком и приблизительным временем воспроизведения.
- Команды: следующий, предыдущий, пауза (заполнение эфира тишиной), продолжить, перемотка, запуск любой песни из списка.
- Команда сначала ставится в очередь, затем её реальное выполнение подтверждает программа на ПК. Если ПК отключён, управление блокируется. Токен не хранится в сайте.
- История 36 часов и резервный YouTube-плейлист через 20 минут без PC-сигнала остаются без изменений.

## Как это подключается к ПК
Это обновление добавлено **в GitHub к DJ-движку `scripts/prometei_fm_dj.py`**.
Для новых функций на рабочем ПК должны лежать рядом:
`prometei_fm_dj.py`, `fm_remote_control.py` и существующий `START_PROMETEI_FM.cmd`.

Сначала используй `scan` для каталога, затем запусти `broadcast` с подтверждёнными правами и своим рабочим источником Icecast / YouTube Live, как раньше.
DJ-движок берёт токен из `PROMETEI_FM_DJ_TOKEN` или спрашивает скрытым вводом; отправляет только названия, исполнителей и длительности, но никогда исходные файлы и абсолютные пути.

Cloudflare Pages требует существующих `FM_STATE` KV и `FM_DJ_TOKEN` Secret. Пульт и PC DJ должны использовать **один и тот же токен**, который никогда не публикуется в коде или переписке.

## ВАЖНО: старый V4.3 tunnel-плеер
Если на ПК сейчас работает отдельный пакет `PROMETEI_FM_V4_3_PC_FIRST_YOUTUBE_20MIN`, его локальный музыкальный процесс **не обновляется автоматически коммитом в GitHub**. Кнопки не будут менять музыку в нём, пока локальный V4.3-движок не получит поддержку того же /api/fm/control протокола. Сам сайт не может отдавать команды процессам на чужом/локальном ПК без подключённого агента.

## Протокол для совместимых PC-движков
- `POST /api/fm/control` — `{type:"catalog",runId:<hex32>,tracks:[{id:<hex24>,title,artist,durationSec}]}`; стабильный непрозрачный ID (SHA256 относительного имени до 24 символов).
- `POST /api/fm/control` — `{type:"status",runId,trackId,playId,title,artist,durationSec,elapsedSec,state,commandAck,commandResult}`; обновлять каждые ~3 секунды.
- `GET /api/fm/control?poll=1` — с тем же Bearer; брать `command` и исполнять по `runId` только один раз.
- `POST /api/fm/control` — `{type:"command",action:"next"|"previous"|"play"|"seek"|"pause"|"resume",trackId?,offsetSec?}`.
- Все методы авторизуются как `Authorization: Bearer <FM_DJ_TOKEN>`.
- Клиент обязан подтверждать команду полем `commandAck`; отсутствие подтверждения не считается успехом.
- KV согласуется не мгновенно; это не точный таймкод слушателя. Поток может иметь буферную задержку. YouTube-резерв не перематывается этим пультом.

Треки должны иметь разрешение на публичное вещание. YouTube-плейлисты слушаются через официальный плеер, их аудио не скачивается/ретранслируется.
